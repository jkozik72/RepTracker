## Rules that constrain any project (§1)

These come from the MLH contest terms and MLH standard rules. The site reproduces the terms but does not say whether the organizers apply the standard rules to their own tracks.

- **Work happens in the event window.** No work on the application before it. Libraries, frameworks, and open-source code are allowed; reusing your own earlier code is not.
- **Public code.** The repository must be public and stay public after the event to be eligible for prizes.
- **AI coding tools are allowed** and should be listed in the submission.
- **Be there for judging.** The team demonstrates the project live; all members take part.
- MLH's published criteria are originality (25%), technical complexity (25%), adherence to theme (25%), and practical implementation (25%). Whether the organizers use them is not stated.

## Combining tracks (§6)

| Combination in one submission | Stated? |
|---|---|
| Department of Computer Science Track + any other track | Yes: "Any idea, any stack, in any track" |
| Capture the Flag + a project track | Capture the Flag "runs alongside" and needs no project; same-person rule not stated |
| Several MLH categories with one project | One application per category; more than one application per event is allowed |
| Any other combination; a cap on tracks per team | Not stated |

Some tracks constrain the build itself: Base44 needs the linked app built in Base44, Future of Money needs the Breez SDK plus a write-up and open source, Code of Life excludes real patient data, and the SpaceXSI raffle needs Cursor as the main coding agent.
